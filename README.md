# Эмулятор командной оболочки ОС

**Практическая работа по конфигурационному управлению**  
**Вариант № 19**  
**Этап 5. Дополнительные команды**

## О проекте

Разработан графический эмулятор UNIX-подобной командной оболочки на языке Python.

Эмулятор позволяет выполнять команды с виртуальной файловой системой (VFS), загружаемой из JSON-файла.

Все операции выполняются в оперативной памяти. Исходные файлы VFS не изменяются.

## Этапы разработки

| Этап | Реализованная функциональность |
|---|---|
| 1. REPL | GUI, парсер команд, заглушки `ls`, `cd`, команда `exit` |
| 2. Конфигурация | Параметры запуска, отладочный вывод, стартовые сценарии |
| 3. VFS | Загрузка JSON, проверка структуры, статистика VFS |
| 4. Основные команды | `ls`, `cd`, `tail`, `uptime` |
| 5. Дополнительные команды | `mkdir`, `rm`, изменение VFS в памяти |

Каждый этап сохранён в отдельной ветке Git.

## Используемые технологии

- Python 3.
- Tkinter — графический интерфейс.
- argparse — параметры запуска.
- shlex — разбор команд.
- json — загрузка виртуальной файловой системы.
- pathlib — работа с путями к файлам.
- unittest — автоматическое тестирование.
- Git и GitHub — контроль версий.

## Поддерживаемые команды

| Команда | Назначение |
|---|---|
| `ls [путь]` | Вывод содержимого каталога |
| `ls -a [путь]` | Вывод, включая скрытые элементы |
| `cd [путь]` | Изменение текущего каталога |
| `cd ..` | Переход к родительскому каталогу |
| `tail файл` | Последние 10 строк файла |
| `tail -n N файл` | Последние N строк файла |
| `uptime` | Время работы эмулятора |
| `mkdir путь` | Создание каталога |
| `mkdir -p путь` | Создание вложенных каталогов |
| `rm файл` | Удаление файла |
| `rm -r каталог` | Рекурсивное удаление каталога |
| `rm -f файл` | Удаление без ошибки, если файл отсутствует |
| `rm -rf путь` | Рекурсивное принудительное удаление |
| `exit` | Завершение работы |

## Запуск

Для запуска требуется Python 3 с поддержкой Tkinter.

Откройте терминал в корневой папке проекта.

### Интерактивный режим

```powershell
py src/main.py --vfs scripts/vfs_stage5.json
```

### Успешный стартовый сценарий

```powershell
.\scripts\run_stage5_ok.bat
```

### Сценарий с ошибкой

```powershell
.\scripts\run_stage5_error.bat
```

### Проверка дополнительных режимов

```powershell
py src/main.py --vfs scripts/vfs_stage5.json --script scripts/stage5_modes.txt
```

## Проверка обработки ошибок

Для пятого этапа подготовлены отдельные стартовые сценарии:

| Сценарий | Проверка |
|---|---|
| `stage5_error.txt` | Создание существующего каталога |
| `stage5_error_missing.txt` | Удаление отсутствующего файла |
| `stage5_error_parent.txt` | Создание каталога без родителя |
| `stage5_error_directory.txt` | Удаление каталога без `-r` |
| `stage5_error_root.txt` | Попытка удаления корня VFS |

Пример запуска:

```powershell
py src/main.py --vfs scripts/vfs_stage5.json --script scripts/stage5_error_root.txt
```

Стартовый сценарий останавливается при первой ошибке.

## Работа с виртуальной файловой системой

VFS хранится в JSON-файле и загружается в оперативную память при запуске эмулятора.

Каталоги представлены объектами с полем `children`, файлы — объектами с полем `content`.

Команды `mkdir` и `rm` изменяют только загруженную структуру VFS.

Например:

```text
ls
mkdir temporary
ls
rm -r temporary
ls
```

Изменения видны другим командам во время работы эмулятора, но не сохраняются в исходный JSON.

При следующем запуске VFS загружается заново.

## Автоматическое тестирование

Для четвёртого этапа реализованы автоматические тесты на основе `unittest`.

Запуск:

```powershell
py -m unittest discover -s tests -v
```

Проверка синтаксиса Python:

```powershell
py -m py_compile src/main.py src/vfs.py src/commands.py
```

## Проверка неизменности VFS

Для проверки можно вычислить SHA256-хеш JSON-файла до и после работы эмулятора:

```powershell
Get-FileHash .\scripts\vfs_stage5.json -Algorithm SHA256
```

При отсутствии ручных изменений файла значения должны совпадать.

## Обработка ошибок

Реализованы проверки:

- Некорректного формата VFS.
- Отсутствующего файла VFS.
- Неизвестных команд.
- Неправильных аргументов.
- Несуществующих файлов и каталогов.
- Попытки создания существующего каталога.
- Попытки удаления каталога без рекурсивного режима.
- Попытки удаления корневого или текущего каталога.

## Ограничения

- Эмулятор поддерживает учебное подмножество UNIX-команд.
- Не все параметры настоящих UNIX-утилит реализованы.
- Файлы VFS содержат текстовые данные; отдельная поддержка двоичных данных не реализована.
- Изменения VFS не сохраняются между запусками.
- Команды не изменяют реальную файловую систему компьютера.
- Автоматические тесты представлены для функциональности четвёртого этапа; пятый этап проверяется стартовыми сценариями.
